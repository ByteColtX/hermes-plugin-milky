# Design

## Context

动机与范围见 proposal.md。当前插件配置只读环境并在平台注册时固定；表情包服务已经提供显式命令维护和共享持久库，但没有 Web 上传、预览、分页或持久任务。列表还可能初始化存储，现有进程内协调不能证明 Dashboard 与 Gateway 同时维护文件安全。

本次只读核对的 Hermes core 为 b3a1900e72。证据位于该仓库的 Dashboard 扩展指南、配置指南、插件开发指南，以及 Dashboard 发现/路由、插件 settings、profile 和认证客户端实现。源码确认存在声明式 Dashboard 资源和 API、认证上传/下载、插件设置写入及插件持久目录；未验证实际安装、代理前缀、profile 切换与任务关闭。

项目主规范对仅环境配置、唯一入口和维护命令来源的描述需要显式修改。配置主规范列出的 25 项是 Milky Action 工具，当前 manifest 还包含两个独立贴纸工具；本变更保留两者，不以旧计数删除已实现工具。新增 Dashboard 入口是宿主管理扩展，平台仍由根入口注册；Web 维护独立认证不意味着现有命令突然具有 operator-only 保证。此次规划不更改其他未归档 change 的进度和证据。

## Goals / Non-Goals

**Goals:**

- 同一套业务校验与维护规则服务 Web 和现有入口，配置解析、持久化、运行快照各有清晰职责。
- profile 是配置、图库、任务和凭证解析的一致作用域；浏览器提交的路径和当前 QQ 会话均不参与确定存储根。
- 长任务、文件提交与并发冲突具备可验证终态，页面刷新和网络重试不会隐式重复变更。

**Non-Goals:**

- 不添加独立服务器、登录系统、通用 QQ Action、试发或自动入库，不复制宿主入站下载体系。
- 不改变搜索/发送工具契约、成功统计规则或未实施的会话图库方案；不承诺运行中热更新。
- 不要求修改 Hermes core；缺失必要能力时明确不支持，不通过 monkey patch 补接口。

## Decisions

### 1. 使用宿主声明式扩展，管理层独立于 QQ 连接

在插件目录交付 Dashboard 清单、预构建页面和宿主可挂载的 API。真实安装使用宿主已启用的用户插件位置；当前 core 不挂载项目本地插件的 Python API，因此不能把工作区内页面被发现当作后端可用。页面使用宿主 SDK 的组件、主题、JSON 和二进制认证客户端，媒体通过认证请求取得浏览器临时对象，不生成不受保护的静态图床。只读浏览不启动维护 worker；Web 导入不依赖平台注册成功，普通 Gateway 不加载 Web 依赖。

依赖方向为浏览器 → 宿主认证与 profile 边界 → 插件管理适配层 → 共享配置/图库服务 → core 持久化与辅助视觉。命令入口同样进入共享图库服务。图库服务不反向依赖页面或 QQ adapter，不创建新的 Milky client。

独立 Web 服务会重复认证与生命周期，直接修改宿主页面会使发布耦合 core，均不采用。原生 Desktop 使用另一套页面 SDK，此次只覆盖 Web Dashboard。

### 2. 配置遵循 core 优先级并保留旧部署

普通设置使用插件 settings 命名空间与原生类型；同一顶层设置键按 settings、legacy config、当前 profile 的旧环境、默认值解析。命中高优先级源后再校验，非法值不继续回退。Will 作为整体对象选源，内部缺失项沿用现有默认值，避免将不同来源的触发规则意外混合。宿主管理覆盖仍由 core 负责。core 通用优先级中的 CLI 覆盖由宿主处理；当前 Milky 没有专用 CLI 配置覆盖入口，本次不新增这一层。

地址、白名单等配置键及类型见 configuration delta。凭证绑定既有环境名，单独走 core 凭证生命周期；不复制到 YAML 或任务记录。配置读取与所有 adapter/sender/home-channel 使用相同解析契约；manifest 和平台发现不能继续把旧地址环境变量设为唯一配置门槛。

Web 读接口分别提供原始显式设置、有效值、来源和可写性。只提交修改键，服务器用最新持久化输入重新构造并校验完整候选。首次配置允许先保存普通值或凭证，但运行完整性仍为未满足。普通设置保存与凭证操作在 UI 中分开，避免暗示跨文件事务。为防旧表单覆盖，使用不透明配置版本检查；对宿主并发写入，沿用 core 的跨进程设置写入保护并核验结果，不声称插件自有锁能控制其他 core 写入入口。当前 core 的逐键写入未提供比较版本后条件提交，因此提交前版本检查只拒绝当时已变化的旧表单；检查到写入之间的外部竞争不能被承诺全部检测，界面需明示并发保存限制，核验差异须刷新。托管拒绝、部分保存和核验失败分别返回实际结果。

不自动搬迁或删除旧环境值，也不在注册时把默认值写进 settings。退回旧插件前需把需要保留的普通设置显式导出为原环境格式，由用户按原部署路径应用；否则旧版本只会看到尚存的旧环境值。

### 3. profile 显式绑定，宿主提供范围

插件页面明确选择一个宿主已确认的 profile，默认绑定宿主确认的启动 profile；插件内部选择控件和每个请求使用同一值，不读取未公开的宿主前端状态。全局切换不可识别时不猜测跟随，页面持续清晰显示自身绑定范围。切换前提示放弃未保存表单，切换后清除旧图选和预览，拒绝旧请求覆盖新视图。

后端通过 core 作用域处理设置、凭证和插件数据目录。任务创建时冻结 profile，后台执行与恢复查询都进入该范围，不能在任务运行中使用另一请求切换后的全局目录。用户插件是否启用按目标范围检查。缺少可信作用域能力时拒绝该操作，不默认选另一个 profile。

此选择基于当前 SDK 不自动为 /api/plugins 请求附加管理 profile 的事实，避免表面上切换了配置却写到另一个图库。

### 4. 上传批次与原命令 inbox 分离

上传的未完成 bytes 存在插件持久根内专用暂存区；完整接收后生成不透明上传对象和批次。Web 入库传递明确候选集合，复用现有图片校验与入库规则；原命令仍扫描其固定 inbox。暂存目录不放在命令递归扫描范围，防止命令消费另一个用户仍在上传的内容。

单图限制沿用现有规范；首版规划默认每批 50 个文件、总 bytes 100 MiB，不支持压缩包和 URL。传输接收有界且按实际 bytes 校验，超额或不完整批次不开始视觉。候选只在成功校验和内容去重后请求 core 辅助视觉，保留原始图片格式与动画。非贴纸与视觉失败分别使用既有隔离/保留语义，按上传对象关联而非原文件名定位。

失败输入可明确重试或丢弃；无活动任务引用的 Web 暂存内容保留 7 天后回收，每 profile 暂存总量规划上限 500 MiB，配额已满拒绝新上传而非删除活动输入。终态清理不扫描命令 inbox 或 junk。图片预览只服务可见库条目，不开放任意暂存/目录下载。

### 5. 维护服务增加共享一致性与只读管理查询

浏览接口独立使用只读库访问，缺库即空库；分页默认与上限沿用已有列表数量边界，新增情绪、标签、描述筛选与稳定排序。预览通过 ID 查可见条目，重新验证文件及完整性，再交付有限认证图片响应；离页和换 profile 释放浏览器临时对象。

所有维护入口共享按 profile/图库的跨进程变更协调。视觉分析在长临界区外执行，提交前复核内容唯一性、条目版本和目标文件；删除/清理不能回收仍有有效引用或正在读取的文件。发送只在本地候选校验与一次性 materialization 阶段参与必要的短保护，不持有跨整个 Milky 网络请求的维护锁。数据库与文件不是单一事务，失败后的可见性和恢复继续依靠既有提交/修复语义，不能把未提交文件显示为成功。

批量操作按明确 ID 与版本执行，逐项提交并回报，不承诺全批原子；人工覆盖语义不变。清理预览绑定计划版本和对象范围，执行前再次检查引用，过期计划拒绝或跳过已变化对象。重建索引不生成新的可见贴纸或重置统计。

### 6. 使用有界持久任务记录与宿主内执行

所有图库变更先记录任务及目标，再由宿主内执行层消费；单项编辑和删除也使用同一重复提交与结果查询契约，纯浏览和清理预览不进入变更队列。任务只存不透明对象引用、有限元数据、状态与计数；每 profile 一次运行一个批次，队列最多 10 个，视觉并发沿用现有上限。同步文件/视觉工作离开 Web 事件循环，不能用不可取消的无限线程掩盖超时。

客户端先取得服务端签发的有期限请求标识，标识绑定 profile、操作及过期时间；重复提交相同标识和内容返回原任务，内容不同返回 conflict。请求标识有效期不超过任务记录保留期，超过期限返回 expired，即使详细历史已淘汰也不能被当作新任务。历史最多 1000 条终态或保留 7 天，配额淘汰后标识返回 expired；采用紧凑的有期限去重记录，活动任务不淘汰。限制发放和提交速率，使去重记录也有界。

页面以有界轮询查看进度，关闭页面不等于取消。取消只阻止尚未开始工作，已完成项保留；同步视觉若无法立即中止，停止新派发并在有限等待后记录未确认结果，不能让晚到结果写入已关闭存储。重新启动按执行者归属核对未终结任务，仅将已确认失去执行者的任务标 interrupted，不修改其他存活实例拥有的任务，也不自动重放。进程意外退出以持久记录补偿，正常停止使用宿主路由生命周期释放资源。插件停用后新请求拒绝，执行层在下一次派发/提交边界重新检查启用状态并停止未执行项。

### 7. 发布与验收基于能力证据

源码审查确认的 SDK 版本为 1.1.0，实际要求按使用的认证请求、组件和路由能力检查；尚未证明最低 Hermes 发行版本。实现先在真实宿主验证扩展发现、作用域、二进制认证和正常 shutdown，再完成浏览器流程，禁止 fake host 通过后宣称真实集成通过。

管理测试使用合成图片、独立 profile 与临时图库；Web 流程不需要 QQ 试发。辅助视觉验证需要可用的真实服务并记录是否实际执行；不可用则保留 blocked。前端构建产物与源码随 directory plugin 共同发布，CI 核查可重复构建和安装资源完整性。当前 Python 构建声明不包含插件包，不能将 wheel 构建成功视为 Dashboard 已随目录发布。真实宿主验证使用显式启用的用户插件安装位置；仅在项目目录中放置 Dashboard 后端不会得到宿主自动挂载。

## Risks / Trade-offs

- [core 配置文档与个别平台历史优先级不同] → 本插件按已确认的通用配置规则和插件 settings 回退实现，测试纯环境、纯 YAML、混合及托管状态，不照搬其他平台的特殊覆盖。
- [宿主私有作用域 helper 或 SDK 发生变化] → 使用最小适配边界和能力检查，真实宿主兼容测试记录版本，不补丁 core。
- [多字段设置和凭证并非同一事务] → 分开保存、先校验再写、逐项核验，失败不虚报全部成功。
- [文件回收与发送竞争] → 所有写入口共享协调，读取保护限于本地读取阶段；测试不同进程竞争与中断恢复。
- [视觉请求耗时或无法撤销] → 有界超时/并发，任务保留不确定结果，停止后禁止晚到提交，不自动重试。
- [只依赖进程内任务导致刷新/重启丢失] → 持久结果、稳定请求标识、重启 interrupted；为有界保留接受历史过期后无法继续查看的取舍。

## Migration Plan

1. 增加统一配置来源解析和 manifest 设置声明，先通过旧部署与纯 YAML 的启动测试；不写用户配置、不删除旧环境。
2. 在图库保持现有 ID、元数据和统计的前提下增加管理读接口、版本/协调和独立任务记录；必要的数据迁移在首次显式维护时进行并可恢复，纯浏览不迁移。
3. 发布包含预构建资源的插件包，按宿主支持的插件发现流程启用 Dashboard；后端代码更新按宿主要求重启服务，不能仅刷新页面宣称新后端已加载。
4. 完成真实 Dashboard 及 profile 隔离、取消/关闭、辅助视觉证据，更新 README、ARCHITECTURE 和 evidence。没有真实环境的项保持待验证。
5. 回滚前停止接收新维护任务并等待/标记活动任务；保留图库、原始图片和任务记录。普通设置按需转回旧环境格式，不自动删除 secrets；旧版本不读取新任务记录，兼容性不能确认时禁止其写入新版本存储。

## Open Questions

- 最低可支持的 Hermes 发布版本需要对已确认接口做发行版映射与真实安装验证；能力缺失时的 unsupported 行为已确定。
- 真实辅助视觉供应商在取消/超时后的资源释放延迟尚无证据；实现不得改变“不自动重放和不接受关闭后提交”的既定契约。
