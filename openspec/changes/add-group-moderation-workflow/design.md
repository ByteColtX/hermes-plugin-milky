# Design

## Context

动机见 proposal.md。当前入站分支经过门禁和 Will 才进入主会话，聊天历史缓冲会被消费；三个现成群管工具仅做参数校验并提交请求，不能当作已具备权限控制。启动查询已取得 Bot 群成员信息，但现有禁言状态不等于管理身份。Dashboard 已有宿主认证和 profile 绑定，维护任务面向图库，不能直接代替群管执行器。

只读证据来自 inbound/pipeline.py、session/dedup.py、session/buffer.py、state/mute_tracker.py、outbound/tools.py、dashboard/ 和相关主 specs；本地 ../hermes-agent 的插件辅助模型、插件存储、Dashboard 挂载与任务生命周期支持本方案。宿主通用审批存在全局关闭和缓存放行语义，部分 hook 故障路径不能独立承担强制授权。本轮未实现或联调这些接入。

## Goals / Non-Goals

**Goals:** 让消息筛查、模型判断、业务授权、协议执行各自具有可检查的结果；聊天与审核分别推进；人工批准可跨 Web/Gateway 进程、页面关闭和重启保留。

**Non-Goals:** 不改 Hermes core；不创建常驻主会话或依赖父会话的子 Agent；不承诺每种语义违规都被本地规则捕获；不把整个 Action catalog 纳入本次改造。

## Decisions

### 1. 独立审核入口和状态所有权

统一消息校验与事件去重之后，在同群有序接纳内完成审核资格判断、本地筛查和有界证据快照。普通聊天仍走既有门禁；审核不受聊天 mute 或 Will wait 阻断，不改 Will 分数、不消耗聊天历史、不额外创建普通 turn。模型工作在独立有界队列中进行，网络等待不占用普通聊天接纳。

Gateway 拥有群身份快照、临时正文上下文、审核队列和唯一可调用 Milky 的执行工作者。profile 持久存储拥有案件元数据、方案版本、批准与逐动作状态；独立受控短期证据区保存审核必需的命中消息及有界上下文纯文本，供 Web 审阅；Web 只读写这些受控记录，不持有 Milky 执行连接。跨进程协作以持久事务为准，不依赖进程内事件广播或假设共享内存。Web 操作者从已验证宿主身份取得；宿主可信本地访问若只提供共享管理员身份，应记录该真实归属而不伪造个人身份，不能确认访问已受保护时拒绝审批。每个 profile/Bot 的执行权须排他，失去所有权的实例不得继续开始 Action。

相比在宿主分发 hook 审核，这一入口能覆盖未触发聊天的消息；相比主 Agent 复用，它不要求已有会话，也不把审批提示发到 QQ。

### 2. 本地规则筛查与独立结构化复核

第一版提供可维护字面词表、精确例外、有限格式规则和按群/成员计数的刷屏规则。词表、规则 ID 和适用群规随策略版本保存；字面匹配先做有限字符规范化，同时保留原文位置映射。拒绝任意无执行上限的正则输入，采用明确受限的规则类型。不选定具体第三方库，实施时根据基准证据选择实现；第三方审核 API 不属于前置依赖。

普通非命中消息只进入该群临时上下文，不调用模型。命中只表示疑似违规。复核输入是版本化群规、命中规则、当前消息及之前 N 条记录，身份和 message_seq 来自已校验协议字段，消息正文作为不可信证据。默认 N=20、历史时间窗 600 秒、总输入正文 20000 字符、单条 4000 字符；包含截断、缺失和顺序信息。截断了决定性证据时不得自动处罚。审核使用宿主独立辅助模型配置，输出违规/无违规/未决、群规 ID、证据引用和有限动作，不继承聊天记忆、SOUL 或工具执行循环。插件自行验证结构和业务语义，不能只相信模型自报置信度。

### 3. 三档模式及受约束动作

以下是用户委托下确定的提案默认值，可在审阅提案时调整。

| 模式 | 明确无违规 | 明确违规且方案合法 | 无法判断、超时、畸形输出或方案越界 |
|---|---|---|---|
| auto（默认） | 关闭案件，不处罚 | 执行 | 持久化待 Web 人工处理 |
| smart（智能） | 关闭案件，不处罚 | 执行 | 留为未决，可在 Web 手动接管 |
| manual（人工） | 关闭案件，不处罚 | 提交 Web 审批 | 待 Web 人工选择方案 |

资格或实时权限失败属于 blocked，不能通过人工批准越过。规则按可选动作和时长上限约束模型；默认允许撤回，允许 300 秒禁言且自动上限 300 秒，默认禁用踢人。操作者可显式开启踢人及调整上限（本地政策最大 7200 秒）；拒绝再次申请默认 false，必须作为独立策略权限和具体方案参数明确启用。本次违规处置不提供 duration=0 解除禁言流程；解除作为后续明确设计的纠正能力，不从违规规则自动生成。第一版不采用隐含的“第几次自动加重”规则；群规可引用同一成员已确认的独立案件统计，但命中、未决、拒绝和重复投递不得计为再次违规。

方案最多包含当前违规消息的一次撤回及对同一发送者的一项成员操作，顺序固定为撤回后成员操作。依赖步骤失败或未知后停止剩余步骤，展示 partial/unknown，不进行隐式补偿或重放。

### 4. 权限以实际执行边界为准

只有有效白名单范围与显式启用群管群的交集参与审核；当前有效白名单为空时不审核或处置任何群；群通配符不自动启用群管。白名单管理命令仍可按既有路由进入 core 授权，但该例外不赋予群管资格。身份仅接受已核实的 admin/owner，未知或 member 阻断审核处置，Web 显示权限原因。复用初始同步结果，实际执行每步之前重新查询自身群身份和目标成员，并校验返回的群/Bot/成员归属。第一版保守地保护 Bot 自身、群主和管理员，只有明确普通成员可受处罚；不猜测上游角色层级能力。

群、成员、消息必须绑定真实案件。审批只认可精确方案版本和参数，变更目标、duration、reject_add_request 或策略版本均使旧批准失效。方案生成后 600 秒失效，这是插件有效期，不是 Milky 撤回时间限制。过期案件继续可查看，但不能凭旧批准执行，需重新复核；临时证据丢失时保持不可执行。

三个既有工具共用上述边界。可信宿主调用上下文必须关联已存在案件及完全匹配的方案；普通模型参数、群正文和通用 approval 标志均不能制造授权。没有可信关联返回 blocked；合法但未批准返回 pending_review 及不透明案件标识并立即结束。当前宿主若不能提供所需关联，直接工具路径保持 blocked，后台案件执行仍可工作。不增加任意参数转发或扩大工具 schema。

### 5. Web 审批持久化但不阻塞会话

待处理、未决、无违规关闭、拒绝、可执行、执行中、成功、失败、部分完成、未知、阻断、需要重新复核分别可见；每次批准/拒绝用案件版本条件更新并记录宿主确认的操作者。Web 先展示群规、规则命中类型、群与成员、消息 ID、上下文数量/完整性、方案动作与参数、版本、权限和过期状态。Web 可通过当前 profile 的宿主认证接口读取独立短期证据区中的纯文本命中消息和有界上下文；响应禁止缓存，切换 profile 清除旧视图。证据区与执行记录分开，默认及最大保留 24 小时、每 profile 总量 64 MiB，存储仅允许运行账户访问；过滤已知凭证、媒体引用、URL 和非正文附件内容，不保存模型原文。页面对过滤、截断、缺失明确标注，不能证明时不批准；过滤影响关键证据时自动决策转未决。满额不能淘汰尚有效证据来制造完整审阅假象，而是拒绝新案件并记录覆盖缺口。过期自动清理，手动提前清理会使相应案件证据不可用。此项明确新增业务证据存储用途，不放宽日志、fixture 和执行记录的正文禁令。

没有方案的未决案件允许操作者依据已有真实目标构造受策略约束的方案，再明确批准；禁止任意群/成员输入扩大范围。重新复核只能复用尚存的本地命中证据且再次执行所有模型校验。pending 不以“主人未及时回应”自动拒绝或执行；动作有效期与证据有效期单独显示。QQ 群、私聊、home channel 均不发审批提示；不用宿主通用审批 transport、会话注入或要求授权的工具 hook。

### 6. 单次执行与结果边界

事件去重识别同一 Bot/群/message_seq，内容相同但序号不同的消息保留用于刷屏判断。案件使用 profile/Bot/群/真实消息序号的持久唯一性，规则版本变化不得把同一消息变成新的处罚次数；缺失序号只做覆盖诊断，不创建可执行案件。

批准被消费前先事务领取具体方案动作，进入发送边界前提交不可重放标记。发送后崩溃或超时的动作进入 unknown，即使实际可能未送达也不自动重试；已确认从未进入发送边界的工作可在权限、版本和时效重新核验后恢复。这选择了“宁可漏一次，也不重复处罚”，不承诺远端恰好一次执行。

后台群管走已验证协议响应契约，只在 HTTP 与 Milky 成功字段均确认时报告 succeeded；明确拒绝为 failed，畸形或传输不确定为 unknown。现成 Tool 远端响应继续保持不透明、原样交付，案件对该路径最多标示“取得响应，业务结果未确认”，不通过解析工具响应重写其结果或日志。统一去重保证工具与后台竞争时只有一方发送。

### 7. 配置生效、容量与隐私

新增群管策略沿用宿主 profile 普通设置及来源优先级、完整候选校验、启动快照和保存后核验；策略没有独立热更新入口。Web 保存显示待重载；执行仅按当前实例已确认的有效版本，不能用仅保存未应用的设置声称已停用。连接重载后重新检查所有待执行案件，旧版本批准失效。已归档的 add-hot-chat-allowlist 已将空白名单改为全部阻止并支持命令热更新；本案复用当前公共有效白名单，且执行前重查，不复制空值匹配逻辑。Gate 增量保留“空名单仍能管理”、core 独占命令授权、管理命令不查询群状态及普通入站按需准备后的授权与撤销代次复查。add-idle-session-wakeup 的定时唤醒不是 message_receive，不进入本地审核，二者不共享正文缓冲或工作队列。本案不依赖尚未实施的空闲唤醒 change。

最多显式启用 100 群；每群近期上下文最多 N+1 条，内存案件快照最多 600 秒，独立短期证据区最多保留 24 小时；每 profile 模型并发 2、待审核 100、活动案件 1000。满载时停止接纳新审核并累加可见覆盖缺口，不阻塞聊天、不静默惩罚、不宣称全部已审。终态展示保留 7 天、最多 1000 条；清理不得删除活动案件和仍在有效入站时间窗内的去重凭证。审核仅接纳接收时已确认时间戳距当前不超过 24 小时的消息，未知/未来异常时间保持未覆盖；去重凭证每 profile 最多 100000 条，满额停止新增可处罚案件，已有凭证不提前淘汰；凭证至少保留至该消息不再具备入站资格，防止记录淘汰后重放处罚。时间窗是本地防重政策，不影响普通聊天接收。

持久执行记录只保留已验证 ID、固定状态/原因、规则与方案版本、结构化操作参数、必要时间和操作者归属；不保存原始工具入参、响应、模型原文或敏感正文。新事件诊断沿现有安全分类；测试只使用合成资料。

## Risks / Trade-offs

- 本地词表漏检和引用误报 → 明示筛查覆盖范围，提供例外词和规则测试，命中后上下文复核；没有本地命中不调用模型。
- 审核证据包含成员正文 → 独立受限存储、认证读取、禁止缓存、24 小时清理及 64 MiB 配额；证据到期后案件保留但不可凭旧批准处罚。已知字段过滤不被宣传为完美敏感信息识别。
- 角色查询与处置之间存在竞争 → 每步刷新并尊重远端拒绝，无法宣称权限检查与远端执行原子化。
- Action 发出前崩溃窗口可能漏执行 → unknown 不自动重放，人工核对结果；不以租约过期恢复发送。
- 其余已注册工具仍存在历史授权缺口 → 文档明确本变更仅覆盖三个群管动作，不宣称全部工具已完成授权改造。
- 断线及背压造成覆盖缺口 → 显示安全计数和运行状态，不承诺 SSE 重放或全量追溯。

## Migration Plan

先交付默认未启用的配置、记录结构及执行控制，再接入本地审核、辅助模型和 Web。实现交付须说明三个旧工具的兼容变化、配置保存与重载的区别。用户在 Web 选择实际群、规则及动作后启用；安装本身不授权处罚。

停用时重新加载配置并停止派发；保留未决、批准和未知结果记录，关闭各自拥有的资源。回滚不得自动恢复旧版无防护工具行为，也不得重放已领取的动作；必要时保持三工具 blocked，并通过后续显式版本修复。

## Open Questions

- 已安装 Hermes 版本的辅助模型输出、profile 存储和 Web 操作者归属是否具备本地源码同等能力：用真实宿主验证，缺失时对应入口明确 unsupported，不改方案绕过。
- Milky 服务对具体撤回时效、管理员操作范围和失败 envelope 的实际支持：以授权后的真实集成证据记录；未确认前保守阻断/unknown，不猜测固定协议限制。
