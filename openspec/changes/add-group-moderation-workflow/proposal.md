# Proposal

## Why

当前插件虽已提供撤回、禁言和踢人工具，但未被聊天触发的群消息不会进入语义审核，工具也没有统一的群管权限与人工审批约束。需要建立先本地筛查、再结合上下文复核、最后执行或转 Web 人工处理的持续群管流程，并避免在 QQ 会话中等待授权。

## What Changes

- 对显式启用群管且命中有效入站白名单的群，持续筛查每条可见的非自身普通消息；采用可维护的本地词表、例外词和有界格式/刷屏规则，只有命中才调用独立辅助模型，附带该群近 N 条上下文。
- 审核与普通会话主 Agent、Will、聊天缓冲分别运行；本地命中是待复核线索，不能直接视为违规或处罚授权。
- 提供按群 auto、smart（智能）、manual（人工）三档，启用后的默认模式为 auto：明确合法方案执行，无法决策转 Web；智能档无法决策时保留未决案件；人工档处置前均由 Web 审批。智能档差异与执行限额是依据用户委托提出的设计默认值。
- 所有处置必须确认 Bot 是目标群的管理员或群主，并在实际调用前重新校验身份、目标成员、有效范围、策略版本与方案有效性。
- 仅支持 recall_group_message、set_group_member_mute、kick_group_member 的受控处置；采用持久案件、单次批准和逐动作防重复记录。未知结果不自动重试。
- 在现有 Web 管理页提供群规、短期证据审阅、待审批、未决、执行结果和覆盖缺口；审批异步持久化，不等待主人在线，不在群聊、私聊或 home channel 发出授权申请，也不调用宿主通用审批。
- **BREAKING**：上述三个既有工具也必须遵守同一群管执行边界；原先仅参数合法即可请求远端的调用可能返回本地 blocked 或 pending_review。已实际取得的工具远端响应仍原样交付。
- 显式启用群管是当前“仅显式工具调用触发状态变更”约束的有限扩展；其余 Action、系统事件和普通消息权限不扩大。

## Capabilities

### New Capabilities

- `group-moderation`：本地筛查、上下文复核、三档决策、权限控制、持久案件及单次执行。

### Modified Capabilities

- `hermes-message-pipeline`：在消息校验、去重和有序接纳后，独立观察符合范围的群消息。
- `inbound-gates`：明确聊天门禁与群管资格边界，保持 Gate 纯确定性。
- `qq-action-tools`：限定踢人自动流程例外，并让直接工具调用接受执行控制。
- `security-boundaries`：规定三个群管工具的本地阻断/待审批结果，保留远端响应原样交付。
- `system-events-and-safety`：明确群管授权来源及 Web 案件例外，禁止会话授权和事件直接处罚。
- `configuration`：增加可验证的群管设置、默认值、策略版本与生效规则。
- `plugin-lifecycle`：增加角色状态、审核任务和持久案件的生命周期所有权。
- `milky-web-dashboard`：增加受宿主认证及 profile 隔离的群管配置、证据查看与异步审批。

## Impact

涉及入站接纳、独立审核状态与持久存储、Milky 身份查询和处置边界、既有三个工具、配置与 Dashboard；实施时更新 ARCHITECTURE.md、README.md、manifest、相关测试及 evidence。复用已检查的本地 Hermes 辅助模型、插件存储和 Dashboard 扩展能力，不修改或替换 Hermes core。

本次仅交付规划；本地源码证明接入点存在，不代表真实模型、跨进程审批或 Milky 群管已联调通过。复用已交付的热白名单与空名单管理命令边界，不依赖尚未实施的空闲唤醒能力。非目标包括图片/语音语义审核、第三方内容审核 API、任意 Action 开放、聊天内审批、自动处理加群/好友请求、全员禁言及对其余工具的全面授权改造。没有本地规则命中的违规、断线期间消息和超限工作不能宣称已覆盖。
