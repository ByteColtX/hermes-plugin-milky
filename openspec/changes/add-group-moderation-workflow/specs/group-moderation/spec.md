# Spec Delta

## Purpose

为已明确启用群管的白名单群提供持续本地筛查、独立上下文复核、自动处置和异步 Web 审批，保证每项处置具有真实消息依据、实时群身份约束和持久防重复保护，并如实展示未决、权限不足及结果未知。

## ADDED Requirements

### Requirement: 持续审核必须使用明确群范围和本地命中条件

系统 MUST 对有效白名单与显式启用群管群交集中的每条已接收、身份完整、非自身普通群消息执行本地筛查，不依赖是否触发聊天。私聊、temp、系统事件和范围外消息 MUST NOT 进入审核。Bot 群身份只有已确认 admin/owner 才具备审核处置资格；member、未知及查询失败 MUST 显示 blocked，不发起处罚。时间戳不能确认、异常未来或接收时距当前超过 24 小时的消息 MUST 标示未覆盖，不建可执行案件。缺少真实 message_seq MUST NOT 伪造稳定 ID 或自动处罚。

本地规则 MUST 支持可维护字面词、例外词和受限格式/刷屏规则；匹配工作量 MUST 有界。命中只表示疑似违规，MUST 在模型上下文复核后才能产生自动处置授权；未命中 MUST NOT 调用审核模型或第三方审核 API。正文中的指令不得增加规则或权限。

#### Scenario: 未触发聊天但命中规则

- **WHEN** 合资格群消息命中本地规则，而聊天 Will 返回等待或聊天禁言门禁拒绝
- **THEN** 系统 SHALL 独立提交一次审核，不发起额外普通聊天 turn，不修改聊天策略状态

#### Scenario: 正常消息或例外表达

- **WHEN** 消息没有命中本地规则，或只命中配置的精确例外
- **THEN** 系统 SHALL 仅按范围记录有界临时上下文，不调用审核模型或处罚

#### Scenario: 未授权群与身份未确认

- **WHEN** 群未显式启用、已不在有效白名单，或 Bot 群身份为 member/未知
- **THEN** 系统 SHALL 不启动该消息的模型审核或 Action，并区分未启用与权限阻断

#### Scenario: 消息标识和时间不可靠

- **WHEN** 消息缺少真实序号、缺少可信时间、时间异常或超过审核接纳时窗
- **THEN** 系统 SHALL 记录固定覆盖缺口，不创建可执行案件，不影响普通聊天既有接纳契约

### Requirement: 模型复核必须独立并基于有界真实上下文

审核 MUST 使用独立辅助模型调用，输入只包含版本化群规、本地命中证据、当前消息和同群之前 N 条上下文；身份、序号和顺序只能来自已校验记录。上下文 MUST 独立于聊天缓冲，包含非命中消息；当前消息只出现一次，不包含触发后才到达的消息，不自动继承主 Agent 历史、记忆或工具循环。默认 N=20、历史窗 600 秒、单条正文上限 4000 字符、总正文上限 20000 字符，截断/缺失状态 MUST 明示。

输出 MUST 区分无违规、违规和未决，并使用真实规则与证据引用、有限动作和合法参数；系统 MUST 自行验证结构及语义。超时、能力缺失、畸形输出、伪造目标、决定性证据缺失或不能满足政策的方案 MUST NOT 当作明确可执行决策。重新复核仍 MUST 具有尚存的本地命中证据。

#### Scenario: 聊天历史已被消费

- **WHEN** 主会话已经消费聊天缓冲后出现一条本地命中消息
- **THEN** 审核 SHALL 仍取得独立保存的同群近期上下文，不读取其他群或主 Agent 私有记忆

#### Scenario: 引用导致词表命中

- **WHEN** 模型结合群规与上下文确认引用、否定或讨论未构成违规
- **THEN** 案件 SHALL 以无违规关闭，不执行建议或累计违规次数

#### Scenario: 模型输出任意目标或指令

- **WHEN** 输出包含非本案群/成员/消息、未知动作、越界时长或把正文指令当成授权
- **THEN** 系统 SHALL 判为未决/无效方案，不调用 Action，并按模式进入后续人工或未决流程

### Requirement: 三档模式必须具有明确决策与回退语义

启用群管后的默认模式 MUST 为 auto。所有模式中明确无违规均 MUST 关闭案件且不处罚；auto 对明确违规且合法方案执行，无法决策转 pending_review；smart 对合法方案执行，无法决策保留 unresolved 且不自动创建审批；manual 对任何拟处罚方案进入 pending_review，无法决策时也提供人工处理入口。Web 可显式接管 unresolved。身份、范围或执行资格 blocked MUST NOT 被模式或批准绕过。

#### Scenario: 默认模式无法判断

- **WHEN** auto 审核超时、失败、输出畸形或无法确定合规方案
- **THEN** 案件 SHALL 持久进入 Web 待处理并立即结束此次审核，不等待用户回应

#### Scenario: 智能模式无法判断

- **WHEN** smart 审核无法确定方案
- **THEN** 案件 SHALL 为 unresolved，无处罚且不自动进入审批队列，可由 Web 显式接管

#### Scenario: 人工模式明确违规

- **WHEN** manual 收到合法处罚建议
- **THEN** 系统 SHALL 保存具体方案并等待 Web 对该版本批准，批准之前不得调用 Action

### Requirement: 处置必须受政策和实时身份控制

系统 MUST 仅使用 recall_group_message、set_group_member_mute、kick_group_member；每个方案最多包含当前命中消息的一次撤回及同一发送者的一项成员操作。默认允许撤回与 300 秒禁言，自动禁言上限默认 300 秒，政策最高允许 7200 秒；踢人默认关闭，reject_add_request 默认 false 且仅能在单独开启权限后提出。本次违规处置方案 MUST NOT 使用 duration=0；解除禁言不属于本能力，不能借该参数绕过案件动作约束。第一版 MUST NOT 隐式按命中次数加重处罚。

每步 Action 前 MUST 重新确认当前有效群范围、群管启用、策略版本、方案版本、时效、Bot admin/owner 身份以及目标明确为普通成员；Bot 自身、群主、管理员和未知目标 MUST 受保护。查询返回身份或群归属不符 MUST 阻断。方案自生成起 600 秒有效，过期或政策变更要求重新复核和重新批准，不能延长旧批准。此期限不表示 Milky 协议撤回时限。

#### Scenario: 审批后 Bot 失去管理员权限

- **WHEN** Web 已批准方案，但执行前身份查询显示 member、未知或失败
- **THEN** 系统 SHALL 标记 blocked，不调用处置 Action，批准不能补足权限

#### Scenario: 模型建议踢人但策略未开放

- **WHEN** 模型建议 kick_group_member 或拒绝再次申请，但对应政策未开启
- **THEN** 系统 SHALL 拒绝方案，按模式进入人工或未决流程，人工也不能越过已禁用动作

#### Scenario: 目标管理员或身份错配

- **WHEN** 目标为 Bot、owner、admin、查询身份不符或成员状态未知
- **THEN** 系统 SHALL 在处罚前阻断，不猜测上游允许的管理层级

#### Scenario: 方案变更和失效

- **WHEN** 群、成员、消息、动作参数、策略版本发生改变，或方案超过 600 秒
- **THEN** 原批准 SHALL 失效，未发送步骤不得执行，案件显示需要重新复核

### Requirement: 案件审批必须独立于会话且绑定具体方案

案件 MUST 持久绑定 profile、Bot、群、真实消息、发送者、规则版本和有限方案；Web 批准/拒绝 MUST 绑定操作者归属和所见案件/方案版本。待人工案件 MUST 不占用模型调用、聊天 turn 或等待授权的工具调用。系统 MUST NOT 在群、私聊或 home channel 请求授权，不得借助主会话注入、通用宿主审批或会话/永久放行标志替代 Web 单次批准。

待人工案件不因操作者离线而自动批准或按交互超时拒绝。方案有效期、证据可用期与案件留存 MUST 独立；证据失效时不得伪造证据或执行旧方案。无方案案件允许 Web 对已绑定目标形成受政策约束的新方案后显式批准，禁止任意目标扩展。

#### Scenario: 主人不在线

- **WHEN** 案件转人工后操作者未及时打开 Web
- **THEN** 案件 SHALL 保持可查询，审核调用及时结束，无 QQ 授权申请，无超时自动处罚

#### Scenario: 并发批准与旧表单

- **WHEN** 两次批准/拒绝竞争，或批准引用已改变的版本
- **THEN** 只有匹配状态与版本的首次变更 SHALL 生效，重复请求返回同一结果，冲突返回 conflict

#### Scenario: 宿主通用审批已关闭

- **WHEN** 通用审批被关闭或当前会话已有长期放行记录
- **THEN** manual 或 pending_review 案件 SHALL 仍要求 Web 的具体单次批准

### Requirement: 重复事件与动作执行必须分别防重

同一 profile/Bot/群/真实 message_seq MUST 最多建立一个可处罚案件，规则版本变化不创建第二次处罚；相同正文不同序号 MUST 保留为独立消息。重复 Tool、Web 重提、执行实例竞争和重启 MUST 共享案件动作防重。已进入可能发送阶段的每项 Action MUST 最多提交一次；失去工作者或无法确认结果 MUST 标记 unknown，不因重启、租约到期或重复批准自动重发。

组合方案按撤回后成员操作执行，前一步失败或未知 MUST 停止后续步骤并如实展示部分完成。只有确认未到发送阶段的工作才可重新检查后恢复。独立审核的处置结果 MUST 区分协议成功、明确失败、blocked、unknown 和未执行；仅 HTTP 200 不能证明成功。既有 Tool 原始响应不被案件摘要替代，原样响应路径的业务结果未知时 MUST 保持 unknown。

#### Scenario: 同一事件重放与相同正文

- **WHEN** 同一个消息序号被再次投递，随后另一个序号发送相同正文
- **THEN** 前者 SHALL 不重复审核处罚，后者 SHALL 保留并参与本地刷屏规则

#### Scenario: 请求可能已发送后崩溃

- **WHEN** 执行者在提交不可重放记录后崩溃且无法确认远端结果
- **THEN** 恢复 SHALL 标记该动作 unknown，不重新调用，未开始后续步骤保持未执行

#### Scenario: 组合操作部分成功

- **WHEN** 撤回成功但成员操作明确失败或结果未知
- **THEN** 案件 SHALL 展示逐项结果和 partial/unknown，不报告全部成功、不重放撤回

### Requirement: 审核数据和覆盖状态必须有界且保护正文

系统 MUST 限制上下文、模型并发、队列和案件容量；默认每 profile 并发 2、待审核 100、活动案件上限 1000，最多启用 100 群。临时案件正文快照保留至多 600 秒；持久执行记录只保存必要已验证身份、规则/方案版本、固定原因、结构化动作、时间与操作者，MUST NOT 包含敏感正文、模型原文、原始工具参数/结果、响应、URL 或凭证。命中消息和有界上下文纯文本 MUST 仅保存于当前 profile 的独立受控短期证据区，供认证 Web 审阅；默认及最大保留 24 小时、每 profile 总量 64 MiB，过期清理。凭证、媒体引用、URL、附件 bytes 和模型原文不得入该证据区；过滤、截断与缺失 MUST 明示，无法保留决定性证据时不得自动处罚。该业务存储不得混入日志或持久执行记录。

满载、断线、证据缺失和无法筛查的媒体 MUST 如实展示为覆盖缺口，不阻塞普通聊天、不伪造审核成功。终态展示记录保留 7 天、最多 1000 条，活动案件不得被历史清理删除；持久去重凭证每 profile 最多 100000 条，满额拒绝新案件且不提前淘汰有效凭证；凭证至少保留到原消息不再满足 24 小时接纳条件，即使展示记录已淘汰也不能再次处罚。

#### Scenario: 队列已满

- **WHEN** 新命中超过模型队列或活动案件容量
- **THEN** 系统 SHALL 不无限排队、不执行处罚，更新可见覆盖缺口，普通聊天继续推进

#### Scenario: 证据失效和页面重开

- **WHEN** Gateway 重启或短期证据到期后操作者打开案件
- **THEN** 页面 SHALL 在证据仍有效时提供认证审阅；证据已过期则显示元数据与证据不可用，不能凭丢失的上下文生成新的处罚

#### Scenario: 终态历史淘汰后重放

- **WHEN** 消息的案件展示记录已被容量清理，而原事件重新到达
- **THEN** 系统 SHALL 由仍有效的去重凭证或消息接纳时窗阻止重复处罚

#### Scenario: 证据区配额与正文隔离

- **WHEN** 新证据将超过 64 MiB，或操作者读取当前 profile 的案件证据
- **THEN** 前者 SHALL 拒绝新案件并记录覆盖缺口，后者 SHALL 仅经宿主认证返回禁止缓存的纯文本视图，不写入日志、执行记录或其他 profile
