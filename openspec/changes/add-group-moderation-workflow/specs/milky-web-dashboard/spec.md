# Spec Delta

## ADDED Requirements

### Requirement: 群管页面必须展示范围规则与运行状态

现有 Milky 页面 MUST 增加群管配置和案件视图，所有读取、写入及查询复用宿主认证客户端、来源保护、插件启用和 profile 边界。页面 MUST 展示显式启用群、模式、群规、本地规则、动作权限、时长限制，以及 Bot 管理身份和运行可用状态；配置来源、保存与应用状态沿用 configuration 契约。系统 MUST 提供不调用模型、不产生处罚的合成文本规则试验，显示命中规则而不声称语义违规。

#### Scenario: 修改群策略

- **WHEN** 操作者保存新的合法群管模式或规则
- **THEN** 页面 SHALL 显示已保存与待重载状态，直至运行实例确认新版本才显示已应用

#### Scenario: 未认证或跨 profile

- **WHEN** 请求未通过宿主认证，插件停用，或案件不属于当前确认的 profile
- **THEN** 系统 SHALL 在读写前拒绝，不泄露案件或执行任何处置

### Requirement: 群管案件审批必须具体可审阅并异步生效

案件列表 MUST 稳定分页（默认 20、上限 100），可按群、模式及状态过滤，显示待人工、未决、无违规关闭、拒绝、等待执行、执行中、成功、部分完成、失败、阻断、未知及需要重新复核。详情 MUST 展示真实群/成员/消息标识、命中规则与适用群规、上下文数量及完整性、有效策略和方案版本、全部动作参数、有效期和逐步结果。详情 MUST 经当前 profile 认证接口提供独立短期证据区的纯文本正文与有界上下文，禁止共享/浏览器缓存、HTML 执行、附件自动加载和跨 profile 引用；正文过滤、截断或过期缺失 MUST 明示，不能暗示仍有完整证据。

批准/拒绝 MUST 携带已看到的案件和方案版本；服务端 MUST 从宿主确认操作者，不信任客户端自报审批人。操作人归属无法确认时拒绝审批。人工修改方案或接管未决案件 MUST 受真实证据目标和动作政策约束，显示具体新方案后显式批准。禁止任意目标、批量默认批准和通过刷新/轮询产生写入。

Web 批准只持久化一次授权，不直接调用 Milky，不等待执行完成，不进入 QQ 会话。响应 MUST 包含可查询案件状态；相同请求重复提交返回原结果，内容/版本冲突返回 conflict。批准过期方案返回需要重新复核，案件本身不因审批交互超时自动消失。

#### Scenario: 主人稍后回来处理

- **WHEN** 待人工案件已持久化，主人稍后打开页面
- **THEN** 页面 SHALL 展示当前证据和方案时效，仍有效者可明确批准，过期者只能重新复核或拒绝
- **AND** 系统 SHALL 没有在 QQ 群、私聊或 home channel 发送授权申请

#### Scenario: 双击批准和轮询

- **WHEN** 操作者双击批准、断线重提或反复刷新进度
- **THEN** 系统 SHALL 保留同一授权结果，不重复提交 Action，不扩大方案

#### Scenario: 部分完成或结果未知

- **WHEN** 处置只有部分步骤成功或动作在途断开
- **THEN** 页面 SHALL 展示每一步实际状态，不显示全部成功，不提供会自动重发未知步骤的重试按钮

#### Scenario: 临时证据不再可用

- **WHEN** 独立短期证据到期或被提前清理，案件仍在列表中
- **THEN** 页面 SHALL 明示上下文不可用，不用空正文假装完整证据，不允许以旧批准执行过期方案

#### Scenario: 覆盖不足

- **WHEN** 审核队列已满、模型不可用、群身份未知或 SSE 曾断开
- **THEN** 页面 SHALL 显示固定原因与覆盖缺口计数，不以零处罚表示全部消息均已审核通过
