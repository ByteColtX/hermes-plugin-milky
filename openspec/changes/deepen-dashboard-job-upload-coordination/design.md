# Design

## Context

动机见 proposal.md。当前路由在检查持久请求身份前重新检查上传候选，原输入已消费或回收时可能拒绝重提；任务实现本身已有原任务去重。上传实现直接了解任务存储与视觉锁，活动引用知识因此分散。主规范要求重提返回原任务，具体差异不视为当前已满足。

## Goals / Non-Goals

**Goals:** 协调 module 隐藏提交、派发、取消、恢复和上传引用回收决策；实现已接收请求重提不依赖旧输入。返回固定分类及有界任务/上传结果。

**Non-Goals:** 认证、配置保存、图库业务合并、新操作、改存储格式、全局 worker、跨进程恰好一次、连接 Milky。

## Decisions

1. 路由只交付已确认 profile 和请求，协调 module 拥有请求签发、提交、查询、取消、上传删除/回收与关闭。图库和上传仍为内部实现；调用方不直接启动 worker、加锁或读取任务存储。仅加路由 wrapper 无法隐藏上传与任务的共享知识，因此 seam 覆盖二者协作。
2. 合法请求先确认 profile、操作内容与持久身份。已绑定且未过期的相同请求直接返回原任务；冲突与 expired 保留原分类。只有首次创建任务才检查候选，并在同一协调保护内记录任务与活动引用。先重新校验旧文件会违反幂等契约，不能继续保留该顺序。
3. 任务记录是持久引用的依据；协调 implementation 同时判断排队/运行引用和仍在途的视觉读取。上传 implementation 只执行受控文件与配额处理，不知道任务表或状态字段。按现有顺序取得图库保护再取得上传保护；视觉/网络等待在保护外，提交前复核取消与归属。锁和查询是内部 seam，不通过外部 interface 暴露。
4. profile 隔离、owner 存活识别、取消/关闭、在途 unknown、逐项进度和重启不重放保留。关闭只影响本实例资源；QQ 生命周期独立，取消等待不代表视觉线程已结束，输入保护持续到实际结束。
5. 存储与文件是 local-substitutable 依赖，使用真实临时目录测试；宿主 profile 与视觉为 true external，沿用生产和 fake adapter。主要测试跨协调 interface，保留 HTTP/profile 专项和存储完整性专项。

## Risks / Trade-offs

- [Risk] 幂等查询被当前候选状态阻断。→ 新增输入消费/回收后重提测试，断言原 ID 和零新增视觉/写入。
- [Risk] 并行删除与提交产生引用空隙。→ 从协调 interface 并发提交/回收，验证新任务不引用被回收输入，活动输入不被删除。
- [Risk] 取消任务后视觉仍读文件。→ 保留实际线程名额与资源保护，迟到结果不能提交。
- [Risk] facade 仍外泄内部知识。→ 架构验收要求路由无手工派发锁协议、上传无任务存储字段知识。

## Migration Plan

先落地幂等差异与引用保护测试，再集中协调实现并迁移路由、上传查询及回收调用；同组更新架构所有权。复用持久记录，不做破坏性迁移。回滚保留数据并恢复原入口；已修复的幂等顺序应保留，不能回退已确认契约。

## Open Questions

真实 Hermes 停止接入和 profile 隔离需实施后 probe；存活 owner 无法确认时继续保守，不把本地 fake 通过写成集成成功。
