# Design

## Context

动机见 proposal.md。当前工具与主规范仅允许查询发送；现有贴纸维护已提供持久化 opaque ID、情绪、标签和短描述，编辑与重新分析保留 ID。候选匹配、当前 chat 的并列轮换、受控文件校验及发送前统计已存在。工具注册和贴纸服务共享插件生命周期，无需新增长期任务或外部依赖。

当前人工库是插件级共享库，只有使用历史按 chat 记录。未归档 add-qq-sticker-library 规划的按会话条目、自动收藏和成功后计数尚未交付。本设计以当前实现为基线，涉及工具注册、只读检索和发送两条路径，因此需要明确接口及兼容性设计。

## Goals / Non-Goals

**Goals:**

- 搜索与查询发送复用候选匹配能力，避免同一查询出现两套过滤语义。
- ID 路径只替换候选选择，继续交给既有发送边界处理，减少回归范围。
- 工具定义与返回结果有界，库、生命周期和使用统计继续由插件所有。

**Non-Goals:**

- 不建立搜索会话、临时 ID、结果缓存或分页状态；不修改 Hermes core。
- 不改变人格、回复频率、SILENT 策略或平台提示；用户自行维护 SOUL/记忆。
- 不引入图片预览、远程检索、别名扩展、scope 迁移或统计语义变更。

## Decisions

### 1. 搜索为可选入口，发送保持互斥双模式

接口沿用 intent/emotion/tags，新增搜索的 limit 和发送的 sticker_id，具体约束见两份 delta specs。统一语法避免同时维护 keyword 与 intent；不接受 index，因为结果顺序可能因库更新而变化。ID 与查询字段同时出现时拒绝，不隐式选择优先级。无需先搜索的调用路径继续存在，避免所有发送都多出一次模型往返。

### 2. 工具发现复用现有可用性，调用时验证当前会话

两个语义工具都只在现有库具备可用条目时展示。注册不访问存储，发现只读探测不创建目录或数据库；handler 先验证参数和可信 Milky 会话，再访问活动贴纸服务。搜索不需要 sender 发出网络调用，但服务解绑后必须返回 unsupported，不能临时创建旁路连接或持久服务。

只读搜索不能复用带创建、迁移或统计副作用的发送存储入口。存储生命周期限定于本次调用，并以只读方式使用现有兼容库；不兼容库不在搜索时迁移。这样在只读介质下仍可查询，关闭服务后无遗留任务或连接。

### 3. 复用词法证据，分别决定展示与发送排序

候选读取和词法证据共享，查询发送继续从最佳匹配池中按当前 chat 历史软轮换；搜索则按相关性取所有匹配候选中的前 limit 条，并列按 opaque ID 字典序稳定排序。搜索不读写轮换状态，既可展示较低层级但合法的备选，也不会因反复查询改变后续发送选择。

搜索只检查当前元数据、文件索引和文件可用性，不为每条候选读取完整媒体、重新视觉分析或创建缩略图。发送前再次完整验证，避免把搜索结果当作文件有效期承诺。当前每次调用仍可能遍历库；limit 约束输出量，不冒充库读取成本的上限。本次不增加缓存或索引迁移。

### 4. 精确发送复用持久化 ID 和统一发送边界

ID 直接沿用已有条目身份，不派生自路径、hash 或搜索排序。按 ID 查询须能区分不存在的条目与存在但文件索引损坏的条目，避免仅通过有效文件关联查询把所有失败都错误归类为 not_found。

得到指定条目后，ID 路径跳过词法排序和轮换，进入与查询路径相同的可见性、受控文件、大小、完整性、统计和单次发送边界。搜索不锁定文件；发生删除或替换时重新验证并失败，不回退其他图。现有文件一次读取和发送前最终核对继续适用；不声称能消除最终核对后所有外部文件并发变化。

不增加“必须是最近一次搜索返回 ID”的服务器状态要求；ID 不是权限凭证，每次发送仍检查当前可见性与会话目标。当前共享库保持原范围，未来作用域迁移必须让搜索与 ID lookup 一起采用新的可见性。

### 5. 最小结果与简短工具说明

搜索返回 status 与至多 10 个限定元数据条目，发送成功继续只返回 status/message_id。ID 模式新增 not_found，其他错误复用现有分类。元数据视为外部数据，不注入平台提示；日志只沿用低基数结果分类，不记录查询或搜索结果。

建议工具描述固定为：

- sticker_search：搜索贴纸，返回 ID、情绪、标签和描述。
- sticker_send：按查询条件或贴纸 ID 向当前会话发送一张贴纸。

参数说明仅用短语，例如“简短意图”“严格情绪筛选”“标签筛选”“返回数量，默认 5，最多 10”“贴纸 ID，与查询条件互斥”。范围、枚举和长度由 schema 表达。bundled skill 仅同步输入、输出和错误语义，不增加场景示例或人格指导。固定轻量描述比堆叠 few-shot 或常驻调用教程更符合用户的上下文预算选择。

### 6. 明确与未完成规划的集成顺序

本 change 独立建立在当前人工库上，不以 add-qq-sticker-library 或 preserve-milky-tool-results 完成为前置条件，也不改动其规划。未来 library change 需显式协调：保留本次 intent 直发兼容性、合并重复 sticker_search 工具、决定 category/keyword 的必要性、迁移共享库条目可见范围，并单独决策统计从 claim 到成功计数的变化。不能将两份冲突契约直接同时宣称为当前能力。

现有 qq-sticker-send 含重复概述和详细要求，本 delta 同步修改禁止 ID、查询排序适用模式以及 not_found 分类的相关条目，保留发送回执不返回 ID 的要求。qq-action-tools 对远端 operationId 的契约保持原状；本地搜索无远端 envelope，既有 sticker_send 的语义回执也不借此重构。

## Risks / Trade-offs

- 文字描述无法完整传达梗图语气 → 首版明确只按元数据选图，素材标注质量单独评估，不宣称视觉理解已验证。
- 搜索增加工具往返和 token → 保留直发入口、限定结果数量和字段，工具描述不携带行为教程。
- 词法匹配仍会漏掉同义表达 → 搜索不宣称改善召回；后续仅在有证据时扩展匹配。
- 搜索到的条目随后被删除或损坏 → ID 发送重新验证并返回明确分类，绝不静默换图。
- 发布后旧宿主或旧会话仍缓存工具定义 → 在真实 Hermes 验证重新发现或新会话的定义，按宿主支持方式刷新，不修改 core 缓存逻辑。
- 外部自然使用意愿取决于 SOUL、模型和素材 → 自动化验收以工具契约为准；用户风格配置下的 A/B 行为观察作为独立证据，不设固定发图率承诺。

## Migration Plan

1. 添加工具注册和双模式接口，同步 manifest、文档、bundled skill 与契约测试；保持现有条目 ID、文件和统计不变，预计无需持久化迁移。
2. 验证已有库和只读库、新旧工具调用、空库发现、重启后 ID 复用以及 unknown 不重试。文档仅在实现证据成立后更新为已交付。
3. 真实 Hermes 验证工具定义、搜索结果交付和新会话发现。真实 Milky 发送仅在明确获得测试目标授权时执行；没有环境或授权时记录 blocked/未验证，不以 fake 或 skip 替代真实成功。
4. 回滚到旧版时移除搜索工具并恢复旧 schema，库和统计不回退、不删除；旧版收到残留 ID 参数继续按原契约拒绝，刷新工具定义或新会话后恢复原查询发送路径。
