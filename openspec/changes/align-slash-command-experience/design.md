# Design

## Context

动机与范围见 proposal.md。当前只有一个插件注册命令 /milky，下有实现信息、sticker、allowlist 三条功能路径；Hermes 内置命令由宿主负责。allowlist 已有可复用的用户体验基线，sticker 业务结果还被 Web 维护、搜索/发送测试使用，不能把业务结果整体换成中文字符串。

本设计跨命令分发与两个业务域，规划展示、固定语法增量和只读运行状态查询。主规范要求安全分类，现有测试部分将英文前缀或 JSON 序列化当作契约；delta 明确区分分类语义和用户可见文本。未归档的自动贴纸、群管、关系、空闲唤醒均不视为已交付命令。本次不改变主 specs 或已有 change，只在实施完成后按 OpenSpec 流程同步。

## Goals / Non-Goals

**Goals:**

- 用一套静态帮助和反馈约定覆盖全部已交付插件命令，文案依据真实结果生成。
- 命令展示只消费经校验的业务结果和本地运行快照；status 需要的状态由生命周期拥有者维护，不增加主动网络探测、后台轮询或持久化。
- 同时验证可读性与语义边界，使文案更新不削弱既有业务测试。

**Non-Goals:**

- 不创建新的命令注册系统、通用 Action catalog、国际化框架或输出格式切换设置。
- 不合并 client、白名单管理器和贴纸存储的状态，不扩大命令授权或 profile 来源保证。
- 不把 slash 文本视为程序接口，不改变 Web/Tool 的结构化消费者。

## Decisions

### 1. 简洁优先，统一短帮助

帮助与查询采用功能标题，操作与失败采用结果标题。标签使用半角冒号，段间一个空行，命令行缩进两个空格；说明以中文为主，命令 token、来源值保持原文。

借用 man 常见的参数记法，不套完整 man-page。帮助只保留 Usage、Commands，以及确有必要的参数说明和少量示例；不增加 NAME、DESCRIPTION 等重复章节，不要求每页都有 Options 或 Examples。方括号表示可选部分，尖括号表示待替换值，省略号概括后续参数；实际合法参数以各分支为准。默认行为用一句话说明，Commands 只列真实子命令。

顶层帮助：

~~~text
Milky · 命令帮助

Usage:
  /milky [command] [args...]

不带参数时查看实现信息。

Commands:
  status      查看运行状态
  sticker     维护贴纸库
  allowlist   管理会话白名单
  help        显示帮助

子命令帮助: /milky <command> help（sticker、allowlist）
~~~

allowlist 在 Commands 末尾用一行 e.g. 给出 add/del 共用的目标示例，省去独立目标章节和重复示例：

~~~text
Milky · 会话白名单

Usage:
  /milky allowlist [command] [args...]

Commands:
  list          查看名单
  add [target]  添加规则
  del [target]  移除规则（别名 remove）
  help          显示帮助

  e.g. target: group:123456、dm:654321、group:*、dm:*

add/del 省略目标时使用当前会话。
不带子命令时显示帮助。
~~~

list/help 不接受目标或其他参数，通用 [args...] 不放宽该限制。既有白名单规范要求 Targets、Examples 分段，需要在本 change 的 hot-chat-allowlist delta 中明确替换，不把旧布局作为例外保留。

协议信息仍用“Milky · 实现信息”标题和已有中文字段标签。status、列表及操作回执保持短摘要，不套帮助章节，也不在成功摘要末尾强行添加帮助提示。

### 2. 帮助先于运行依赖，保留无参数查询

/milky help 是新顶层帮助；/milky sticker 与 /milky sticker help 等价；allowlist 保留空参数与显式 help 等价语义。只接受上述固定 help 语法，不隐式支持 help 后附动词、任意 --help、模糊补全或新增 info 命令。help extra 始终是格式错误。顶层 Usage 中的 [args...] 只概括子命令各自接受的参数，不表示 status/help 接受任意参数；status 与 help 均不接受附加参数。

保留无参数 /milky 查询是兼容性选择；改成顶层帮助会改变已有运维入口。空 sticker 目前是错误，改为帮助能直接改善发现路径。帮助通过 core 后只使用静态内容；无连接、多连接、图库缺失、配置不可用都不阻止静态帮助生成。静态可生成不等于白名单外可路由，后者继续使用现有专属规则。

贴纸帮助的 Commands 展示所有维护动词及各自参数；Options 集中解释 dry-run、limit、edit 字段、合法 emotion 枚举和约束，避免在格式错误中倾倒整个手册。Examples 只保留两个能说明复杂参数的示例，其余合法用法直接见 Commands：

~~~text
  /milky sticker add --dry-run
  /milky sticker edit demo_id --clear=tags
~~~

edit 帮助明确至少一个 set/clear，标签、描述和枚举以既有契约为准，description 不跨空白 token，不承诺 shell 引号语法。增加 sticker remove 仅作为 del 的等价拼写；帮助主展示 del，括注“别名 remove”，不增加二次调用或确认步骤。

### 3. 错误提示定位到用户正在使用的命令层级

未知顶层分支展示顶层简短 Usage；未知 sticker 动词展示贴纸动词集合；已知 sticker 动词错误展示该动词的合法语法。allowlist 同样按动词给出就近语法：add/del 显示可选目标，list/help 不显示目标；未知动词仅显示动词集合和帮助入口。

示例：

~~~text
指令格式不正确。

Usage:
  /milky sticker del <sticker_id>

Help:
  /milky sticker help
~~~

使用 remove 时规范用法仍展示 del 并由帮助说明别名。错误输出只使用预定义安全文案，避免引用非法 ID、路径、token 或整条输入。相比自动纠错并执行，返回明确帮助更可预测，也不会对误拼写产生副作用。

### 4. 展示从结果向外转换，不改变业务状态所有权

依赖方向为：宿主授权与分发 → 插件参数与运行条件检查 → 原有业务操作 → 安全文本展示 → 既有发送。静态帮助和格式错误在业务操作前结束。展示约定只拥有模板、标签与状态映射；client 仍归 adapter，白名单持久化与在线发布仍归管理生命周期，贴纸维护存储仍按单次维护资源边界打开和释放。

共享静态标题、段落规则和格式错误结构，业务域提供自己的状态解释与受限数据。无需把全部业务结果强行包进一种新数据模型，也不让白名单依赖贴纸模块。allowlist 的业务结果文案作为回归基线，帮助与格式错误按统一的简洁约定调整。

Web 和其他结构化消费者继续使用原结果，不解析 slash 文本。搜索/发送测试中的数据准备改用已有业务入口；保留独立的 slash 路由与最终文本测试，避免迁移后只测试业务而遗漏用户输出。

### 5. 状态映射必须保留结果确定性

下表是计划采用的文案方向，内部分类不改名；同一分类在不同操作中可以有准确的中文说明，但不能丢失区别。

| 场景/分类 | 用户可见标题或说明 |
| --- | --- |
| 无唯一可用协议信息连接 / unsupported | Milky 信息暂不可用；请检查插件连接状态后重试。 |
| rejected | 查询请求被拒绝；请检查 Milky 服务的访问设置。 |
| malformed | 无法读取 Milky 信息；服务返回的信息格式不正确。 |
| http_error | Milky 服务请求失败；请检查服务状态后重试。 |
| transport_unknown | 无法确认查询结果；请检查连接状态后重新查询。 |
| updated / reanalyzed / deleted | 已更新贴纸 / 已重新分析贴纸 / 已移除贴纸，随后显示条目 ID |
| sticker_not_found | 贴纸不存在；请查看贴纸列表并确认条目 ID。 |
| missing_file | 贴纸文件缺失；明确没有恢复文件，不把 reindex 当作图片恢复工具 |
| not_sticker | 本次未更新贴纸；本次分析判定为非贴纸，已保留原条目。 |
| visual_unavailable | 贴纸分析暂不可用；按该操作已保证的语义说明候选或原条目保留 |
| conflict | 更改未保存；条目已发生变化，请确认最新状态后再操作。 |
| storage_error / 未知提交结果 | 贴纸维护未完成；无法确认全部结果时先提示核验，不承诺未执行或自动重试 |
| unsupported（贴纸） | 贴纸维护暂不可用；请检查插件存储支持。 |

allowlist 继续沿用已保存并生效、已保存尚未生效、规则已存在/不存在、托管限制、竞争与未知等现有文案；不加入其他异常回执中的查看名单命令。

### 6. 列表与批次用事实支撑可读摘要

列表采用逐条 ID 与中文字段标签，情绪显示中文含义和可复制枚举；来源注明人工/视觉并保留字段级差异。保留既有格式、大小、创建时间、使用次数与最近使用时间，空最近使用时间显示“尚未使用”。数量写“本次显示 N 条”，不推断全库总量。协议版本和来源属于技术事实，保持已确认原值。

批次输出按操作显示分类计数，成功条目 ID 保留。通用 ok 只表示批次结果可读取，必须继续检查其中失败、延后和缺失的计数。各计数可能分别统计候选或文件，不强制合成为一个总数。空 inbox 写“没有待处理的图片。”，不写“新增成功”。

下面是部分导入的版式片段；正式回执按实际结果补齐计数及已创建 ID：

~~~text
贴纸导入部分完成

已添加: 3
视觉分析失败: 1
延后处理: 2

失败和延后的候选仍待处理。
~~~

预览使用“贴纸导入预览”或“贴纸清理预览”标题，以待添加/待隔离/待清理描述计划；末尾明确“未作更改。”。add 预览逐个保留受限情绪、标签、描述与判定，用候选序号区分，不虚构 ID 或展示原文件名。长列表和批次不在展示层额外截断，由既有发送路径处理。

### 7. status 使用本地观察，不宣称端到端健康

/milky status 展示当前实例的运行摘要，与无参数 /milky 的协议端版本信息区分。现有 adapter 就绪先于 SSE 建连，重连退避期间也可能仍保持就绪；因此采用“插件: 运行中”和单独的“事件流”字段，避免“连接: 正常”暗示已经验证 Action 服务、QQ 登录和收发全链路。

建议正常输出如下，半角冒号与其他命令保持一致：

~~~text
Milky · 运行状态

插件: 运行中
事件流: 已连接
本次运行: 2 小时 18 分钟

运行白名单: 6 条规则
白名单配置与当前运行一致。
~~~

插件状态从本实例生命周期观察取得；事件流由拥有 SSE 的组件发布首次连接中、已连接、重连中、已停止或未知的状态。首次建连失败后的退避/再次尝试也显示重连中。只有成功建立事件连接且尚未观察到断开时显示已连接；无消息到达不等同于断开，存在任务或 client 不等于已连接。状态描述的是本地当前所知事实，不能保证尚未被传输层发现的网络中断不存在。实现补充这一只读观察能力，不能读取日志文本或私有资源指针来猜测状态。

本次运行从当前实例完成初始同步并进入运行阶段开始，用单调经过时间计算。SSE 内部重连期间继续累计；disconnect、停止或失败后不继续累加，新运行代次重新计时。少于一分钟显示“不足 1 分钟”，其余按天/小时/分钟显示非零部分且舍去秒；不是进程启动时间、累计在线时间或事件流连接时长。

状态读取绑定到本注册作用域的可信 profile/实例，不能从进程环境、最近聊天或多个活动 client 中猜选。无唯一可确认实例、实例与当前 profile 的归属无法确认或读取期间实例失效时，整条返回“运行状态暂不可用”及简短原因，不伪造停机、零时长或零规则。仅当当前实例确已绑定且可观察到启动、停止或失败阶段时才能显示对应阶段；本次计时尚未开始显示“尚未开始”，停止后显示本次已确认时长；缺失观察能力的字段显示“未知”。无需保留已解绑实例用于事后诊断，停止后的本地调用可以暂不可用。QQ 连接实际不可发送时不承诺能够从 QQ 收到状态回执。

运行白名单计数使用当前已发布规则集合的字面条目数；一个通配符计一条，不表示放行的会话数。配置一致性只比较同一可信 profile 最新持久有效白名单与当前运行规则，不比较 token 或其他插件设置；只读复用宿主配置读取，禁止保存、发布、初始化设置或调用名单修改流程。不一致时显示“白名单配置与当前运行不同。”及“请重启 Gateway 以应用当前配置。”；实例及 profile 归属仍可信，仅配置读取失败、配置非法或运行规则版本变化导致比较无法确认时，显示“白名单配置一致性未知。”；若实例归属失效或运行代次变化，则整条返回“运行状态暂不可用”，不把错误当空列表或无限重试。未知配置不遮蔽仍可确认的事件流与计时字段。运行规则为空显示 0 条并说明“当前不接收任何会话的普通消息。”，不宣称插件离线。

status 不列出具体规则、profile 路径、群列表、Bot 账号、服务 URL 或凭证；不请求实现信息、群状态或任何 Milky Action，不打开图库、不启动 SSE 或心跳探测，也不重新加载配置。命令权限由 core 决定，来源仍经过普通 Gate，不能享有 allowlist 的白名单外管理例外。正常响应只沿已有命令发送流程返回，状态生成本身不发额外网络请求。普通入站 Gate 原有的按需群状态准备与回执发送仍可涉及网络；不将 handler 无主动探测扩大为整个收发链路无网络。

## Risks / Trade-offs

- [本地就绪被误当作网络健康] → 分开呈现插件与 SSE，重连期间不能显示事件流已连接，不推断真实 QQ 登录状态。
- [状态读取跨越停止或配置变更] → 复核同一实例代次与规则版本，变化时降级为暂不可用或一致性未知，不拼接新旧状态。
- [用户脚本解析 slash JSON 或英文错误前缀] → README 明示这是展示格式变化；程序消费者继续使用已有结构化接口，不为脚本兼容保留第二套 slash 输出模式。
- [批次 ok 被误读为全部成功，或 dry-run 被误读为已提交] → 对混合结果、零处理、延后、预览和未知分别做可读文本及业务副作用断言。
- [统一帮助误扩大白名单外可达范围] → 保留管理路由识别边界，验证新帮助与 sticker 别名仍受普通 Gate，core 拒绝不执行 handler。
- [中文格式化泄露动态字段或改变发送行为] → 只选择既有安全字段；不以原始异常生成说明，验证合成敏感哨兵不出现在输出，并保留长文本发送回归。
- [主规范部分条目枚举未提及使用统计] → delta 明确 slash 保留已有统计，与主规范专门的使用统计要求对齐，不添加新统计或查询。
- [较详细的贴纸帮助和列表变长] → 参数错误保持局部用法，完整帮助和合法有界列表复用长消息策略，不新增分页。

## Migration Plan

1. 以本案示例和 delta 建立文本契约，迁移业务测试对 slash JSON 的依赖，同时保持现有操作结果断言。
2. 更新帮助、status 状态观察与查询、别名及文本展示，在同一发布中更新注册描述和 README；不迁移数据库或设置。
3. 完成聚焦与完整检查，将 fixture/fake host 与真实 Hermes/QQ 证据分别记录；仅在真实授权测试环境存在时执行真实命令收发验收，无法验证则标记 blocked/unknown。
4. 回退时恢复旧展示、撤销 status 查询与新增状态观察及对应帮助增量即可，业务数据无需回滚；若已执行合法维护操作，其持久结果不能因代码回退被撤销。

本次规划没有未决的范围或兼容性决策。真实 QQ 字体、分块和转发后的阅读效果仍待实施后的验收，不将本地文本快照等同于真实集成通过。
