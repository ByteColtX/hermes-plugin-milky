# Design

## Context

动机见 proposal.md。现有规范化层已分离展示正文和策略文本，但仍将提及展示加入策略文本；routing 与 willingness 共用该输入。此变更跨越规范化和两种策略，需统一关键词来源及边界。

## Goals / Non-Goals

**Goals:** 三类关键词采用同一来源，排除结构化展示并保留连续文本边界。

**Non-Goals:** 不调整基础增益、概率、扣费、提及目标判断、配置字段或展示正文；不增加状态、持久化或外部查询。

## Decisions

- 规范化层负责生成不可变的连续文本区间，WILL 只消费该快照。顶层相邻 text、markdown 可拼接，每个非文本片段结束当前区间。
- routing、强制条件和兴趣倍率共用区间内子串匹配。明确的空区间表示无可匹配内容，不回退到展示正文。
- 保留旧的显式策略文本输入兼容性：调用方未提供区间时，显式文本视为单一区间；生产规范化路径始终提供区间。
- 不采用在展示字符串上正则删除 @ 的方案，因为它无法区分用户手输文本与结构化提及。也不注入空格或哨兵作为匹配分隔符，避免包含分隔字符的配置关键词跨界命中。

## Risks / Trade-offs

- 文本跨非文本片段原本可被拼接命中 → 新契约明确禁止该行为，增加跨片段与相邻文本的成对回归。
- 三种关键词规则实现漂移 → 共用同一输入匹配边界并验证确定性结果和明确增益数值。
- 仅有本地证据 → 使用合成事件、fake host 验证，不宣称真实 Hermes/Milky 集成通过。

## Migration Plan

无需配置迁移或依赖更新。修复后重载插件生效；回滚代码会恢复旧匹配行为。实施进度与验证证据记录在 tasks.md 和 evidence.md。
