# Design

## Context

动机与范围见 proposal.md。当前配置、Gate 与群状态扫描各自持有启动白名单；命令在普通 Gate 后异步交给 Hermes，命令服务只显式收到参数文本。Web 已通过宿主逐键保存插件 settings、检查托管限制和读回核验，但明确没有跨入口条件事务，也不确认运行实例是否应用。

本地 Hermes 源码显示：命令分发会绑定会话上下文，管理员策略在未配置列表时关闭门禁。插件必须遵从 core 的允许或拒绝，不额外要求管理员证明。会话读取还存在环境回退，因此默认目标和 profile 归属不能从进程环境推断。当前证据为静态源码，尚无本能力的 fake host 或真实集成通过记录。

本变更跨越 core 分发衔接、持久化、运行状态、初始化与兼容迁移，需要完整设计。

## Goals / Non-Goals

**Goals:**
- 保证白名单管理指令在空名单时可到达 core 授权入口，同时普通入站默认拒绝。
- 让持久配置、当前有效策略和群状态各有明确所有者，用户能区分保存与在线应用。
- 通过可测试的提交边界处理并发、撤销、重连、停止与回执失败。

**Non-Goals:**
- 不修改 Hermes Core，不重写内置命令或队列，不新增数据库、黑名单或模式字段。
- 不实现任何 slash 权限策略，不重复 core 的管理员、角色或命令许可判断；不让普通正文或 Agent Tool 隐式修改白名单。
- 不热加载所有配置，不实现 Web/人工配置编辑到 Gateway 的跨进程推送。
- 不撤销宿主已经接受的任务，不重定义出站工具、home channel 或 cron 授权。

## Decisions

### 1. 当前 profile 的宿主 settings 是唯一持久来源

复用宿主设置边界，仅提交 allowed_chats 一个键；普通配置来源顺序保持现状。候选基于最新有效配置，纯环境部署首次实际修改提升为 settings，不回写环境。将现有 Web 保存的通用校验、托管检查、版本和核验能力抽出为与 HTTP 无关的共享边界，使 QQ 与 Web 避免形成两份保存规则。

不采用单独文件或数据库：它们会引入覆盖顺序、恢复与 Web 不一致问题。Web 仍保存后待重新加载；list 同时显示持久规则和运行规则，避免把 Web 保存误认为热生效。持久值与运行值不一致时，无变化的 add/del 不偷偷充当 reload；明确提示需要重新加载，实际修改则基于最新持久值生成完整候选。

### 2. 活动实例拥有运行策略与调用关联

每个明确 profile 的活动实例拥有不可变规则快照、递增策略版本、会话撤销代次及管理提交互斥。Gate 和群扫描范围读取同一策略源，不再各自固定复制启动列表。实例断开先关闭管理接收并失效调用关联，再等待/取消所属操作；新连接从当前 profile 的持久化来源重新解析白名单，其他配置维持各自现有生命周期。

注册路径必须同时改造：当前 __init__.py::register() 只调用一次 load_config()，adapter_factory 永久捕获同一 milky_config；Hermes 的普通 adapter 创建不会重新 register。注册时保留其他配置的既有快照，但将绑定当前 profile 的白名单读取器通过 adapter_factory 注入每个 MilkyAdapter，读取器不得捕获注册时的 allowed_chats 结果或原始 settings 字典。读取器复用配置来源优先级与校验逻辑，每次调用读取当前有效 allowed_chats；不是重载整个 MilkyConfig，不顺带改变连接、凭证、standalone sender 或 home-channel 快照。

每次完整 connect()（包括同一实例 disconnect 后再 connect，以及原 factory 创建的新实例首次 connect）在群扫描、Gate 开放和 SSE 启动前调用该读取器，以新规则初始化统一策略及 MuteTracker。只在构造函数读取不足以覆盖同实例重连。读取或校验失败时连接不得 ready，不回退注册旧值；纯 SSE 传输重连不调用读取器。注册和构造仅装配读取能力，不启动网络或长期任务。测试必须只 register 一次，修改持久设置后分别走这两条连接路径，不能靠重新注册或强制插件发现掩盖旧闭包。

经过 canonical、去重和自身拒绝后，将真实消息来源随既有命令通道交给 core。管理 handler 在 core 分发后取得当前调用的来源会话、profile 和唯一活动实例，用于缺省目标与设置归属；调用结束、取消或实例停止后不能借用旧关联。命令授权始终由 core 执行，插件不签发或消费授权凭据，也不因 core 允许的别名展开或调用者非管理员而再拒绝。

优先复用宿主当前调用的可信会话上下文；若需要插件携带关联数据，只绑定来源、profile 与活动实例，不加入角色、管理员匹配或独立授权标志。缺少可信目标/profile/活动实例时返回 unsupported，原因是无法确定操作对象；不以此补造 slash 权限策略。实现时必须用当前本地 Hermes 的真实插件分发路径证明上下文可达，不能只用直接调用 handler 的 fake 代替。

### 3. 所有 slash 权限由 Hermes core 独占

插件只注册和实现命令，不读取、解析、缓存或重新计算 allow_admin_from、group_allow_admin_from、user_allowed_commands 等权限配置，不调用管理员判断函数充当额外门禁，也不维护角色、子命令 ACL 或权限热加载逻辑。所有 slash 指令使用既有 core 分发和权限结果，core 拒绝则 handler 不执行，core 允许则插件只校验参数与执行条件。

当前 core 按顶层 milky 授权，因此允许普通用户执行 milky 时，也允许其使用 allowlist 子命令；未配置管理员而关闭门禁的行为同样属于 core 决策。插件不把它重新解释为拒绝。需要更细命令许可时由 core 的能力和配置承担，本 change 不修改或替换 core。合法管理目标覆盖当前 profile 的 group/dm 规则，不按来源群角色增设限制。

### 4. 管理读写与普通入站群状态分离

路由例外只由纯文本直接管理指令的语法形态决定，不判断发送者身份或管理员资格。保留 canonical、自身消息拒绝、去重和同 chat 入站顺序，将候选命令连同真实来源交给 core。其他命令和普通正文仍使用既有会话 Gate；这些是会话接入与传输条件，不是插件的 slash 权限策略。已放行会话中 core 支持的别名照常由 core 处理，插件不新增别名权限规则。

core 放行后校验完整参数及当前会话/profile/活动实例，随后读写名单，不查询来源群或目标群状态，不因禁言限制阻止规则管理，也不生成禁言提示。core 拒绝时不会触发管理读写。回执遵守既有发送边界，未送达不回滚或重放修改。

新增具体群或 group:* 直接保存字面规则，不展开通配符，不在修改时扫描群列表或查询成员。群首次收到获准入站的消息时才确认群身份并准备 Bot 成员状态；查询前检查自身与白名单，查询后重新检查授权和撤销代次。准备失败、取消、查询期间撤销或确认禁言均拒绝当前普通消息，不改变已经保存的规则。

查询并发、冷却、事件更新与 TTL 归群状态维护边界所有。新增状态准备不得丢失期间收到的禁言事件或覆盖已经更新的快照。移除授权不立即销毁已知群状态，防止管理回执及既有出站失去可发送性判断；状态本身不能绕过白名单。

现有 MuteTracker._select_group_ids() 的空集合返回全部群分支必须改成零目标；显式 group:* 仍选全部当前群。同步日志不能只改计数：空规则使用 scope=none，非空规则保留 scope=allowlist（包括 group:* 和仅 dm 规则），不再用空值生成 all_groups。更新对应日志断言，验证空名单各计数均为零。

refresh_group() 保留仅刷新已跟踪群的职责，不能直接用于新目标或通过移除其检查来隐式注册任意群。增加独立受控的群状态准备入口：确认 Bot 所在群与自身身份后，以 unknown/拒绝状态纳入跟踪，再查询成员信息；查询期间接收并保留该群事件，查询成功后才报告准备完成。失败或取消留下的状态不能视为可发言，当前普通消息不得继续处理；重试仍走既有冷却与并发边界。此入口由获准入站触发，管理命令不调用；纳入状态跟踪本身不改变入站白名单。

### 5. 规则操作直接对应配置条目

slash_commands.py 的顶层参数分发必须明确区分无参数协议摘要、sticker 维护和 allowlist 管理；allowlist 的合法参数进入管理服务，畸形参数返回 invalid_input，不回退 get_impl_info 或 sticker。命令注册帮助同步声明合法子命令，沿用 core 授权，不加插件权限判断。对应 slash-commands delta 必须修改现有 /milky 协议信息 requirement 的合法参数集合并保留全部旧场景。

删除主指令为 del，remove 是插件子命令解析中的等价拼写，统一归一化到 del；两者均属于直接白名单管理路由，不属于其他命令展开的别名。帮助优先展示 del 并注明 remove。两者使用相同参数、默认目标、持久化、回执与 core 权限流程，不重复执行删除。

add/del 只对配置中的字面规则做集合操作：add 为 S ∪ {rule}，del 为 S ∖ {rule}。省略目标取当前完整 chat key；显式目标必须带命名空间，支持已有完整通配符。dm:* 与 dm:123 是独立条目，group 规则同理：已有通配符时添加具体条目仍须添加，添加或删除通配符均保留具体条目，删除具体条目也不改变通配符。不得展开通配符、按覆盖关系合并条目、联动修改其他条目或生成隐式 deny。仅当添加的字面条目已存在或删除的字面条目不存在时返回 unchanged 且不写入。增减回执只报告条目操作结果，不附带覆盖关系判断，也不将删除条目表述为会话已关闭。实际入站与撤销判定仍按完整规则集合匹配。

空参数 allowlist 与 allowlist help 在 core 授权后返回相同静态帮助，不依赖活动实例或读取设置；help 不接受附加参数。帮助与名单标题统一为“Milky · 会话白名单”，帮助使用 Usage、Commands、Targets、Examples 英文栏目和 e.g. 示例。格式错误以独立 Usage/Help 区块紧凑提示，名单来源使用 Source 标签；异常回执不附加查看命令。

list 稳定排序并完整返回规则，不支持分页参数；配置与运行一致时只显示一份，不一致时分别展示“当前配置”和“当前运行”。来源保留 settings、legacy、environment、default 原名称。空名单说明普通消息拒绝，差异或已保存未应用提示重启 Gateway。提示使用正式简洁的中文，不将内部状态码直接作为标题。长消息沿既有发送流程合并转发或拆分；列表只回到原命令来源，诊断不记录整份名单。

### 6. 保存和在线发布是两个可区分阶段

单实例串行处理管理变更：重新读取持久值和版本，检查托管限制及操作是否有变化，在保存前核对版本和生命周期，执行宿主单键保存并读回，最后无等待地发布完整策略版本与撤销标记。管理流程不发起群查询，普通入站的按需准备遵守同 chat 顺序。

保存失败或托管拒绝不发布候选；已确认保存后发布失败，保留持久值并返回 saved/未应用，重新加载即可恢复。写入结果未知不盲目回滚或重试。可用配置版本只能发现部分外部竞争，不能替代宿主没有提供的跨入口条件事务；这一限制在文档明示，帮助末尾不添加并发说明。

回执不是提交点。QQ 回复失败不撤销设置，也不自动重做修改；管理员可用 list 查验。多个活动实例不能唯一归属时写入前返回 unsupported，本变更不承诺跨进程广播和分布式锁。

### 7. 撤销保护插件待交接消息，不影响已经接受的任务

有效规则发布是生效点。成功回执之后的新消息使用新版本；提交前消息按实际授权检查的旧版本处理，不承诺指令到达即完成。

对实际失去授权的会话更新撤销代次，清理尚未交接的等待消息、待附加系统上下文和 Will 累计状态。异步资源补全后的批次在宿主交接前检查撤销代次，确保删除再添加也不会复活旧正文；检查与交接提交须明确线性化边界，不能让中间等待绕过撤销。正在进行的下载可能已经发生，不承诺回收 Hermes 所有资源。已经提交宿主的任务仍由宿主处理，历史不删除。

此处不把入站授权当作发送权限，不清理出站仍依赖的群状态。移除当前会话的成功回执仍可沿既有安全发送路径发回原来源。

## Risks / Trade-offs

- [Risk] 空值行为改变会令旧部署停止普通接收 → 发布说明明确 BREAKING；需要全部放行的部署显式迁移为两个命名空间通配符。
- [Risk] core 按顶层 /milky 授权，且某作用域无管理员名单时可能关闭 slash 门禁 → 按 core 原有语义执行，不在插件补加管理员条件；迁移文档明确该许可覆盖 allowlist 子命令。core 拒绝所有可用来源时，通过宿主配置调整其命令权限或白名单。
- [Risk] group:* 可能匹配尚无状态的群 → 各群首次获准入站时受控准备，不在未知状态下放行普通消息，不展开保存静态群号。
- [Risk] 以后加入的新群可能尚无状态 → 命中规则的入站可按需确认；查询失败保持拒绝，不新增后台全量扫描。
- [Risk] 宿主未来改变命令调度或上下文传播 → 契约测试与真实分发 smoke 验证，能力缺失返回 unsupported，不能退化成从环境推断操作对象，也不能自行接管命令权限。
- [Risk] 外部 Web/人工写入不能与命令完全原子 → 保存前版本检查与读回核验，报告 conflict/unknown；不承诺发现所有检查后竞争。
- [Risk] 已实现入站规则与尚未实现主动唤醒 change 分叉 → 在落地时核对共享策略读取；主动唤醒保留空名单无候选，改用最新有效规则，不将规划当作当前能力。

## Migration Plan

1. 先建立语法、core 授权衔接、可信来源与持久化/在线状态的契约测试，再统一空值拒绝和运行策略读取。
2. 接入状态准备、管理调用关联、单键核验保存与撤销边界，验证空名单冷启动、停止、重连和实例归属。
3. 更新 README、ARCHITECTURE、manifest 提示、Dashboard 源码及随包预构建文案、CHANGELOG；只在实现和 evidence 通过后声明已交付。
4. 升级前将需要全部放行的旧空配置改为 group:* 与 dm:*；slash 权限按 Hermes core 配置，说明顶层 milky 许可涵盖白名单子命令，不新增插件管理员配置。无需迁移数据库。
5. 回滚插件版本时必须审阅有效 settings：旧版本会把空列表解释为全部放行。不能仅退版本而保留空列表；先停止接收并设置经审阅的非空受限列表，全部关闭需求应在宿主停用平台，避免回滚扩大范围。

## Open Questions

- 目标部署的 Hermes 版本是否保留已观察到的命令调用上下文和 profile 隔离能力，需要集成 evidence 确认；行为已确定为不支持时拒绝，不改变本方案或扩展 core。
- 真实 Milky 上的并发群状态事件、持久化后进程终止和 QQ 回执失败需在获准的测试环境中验证；缺少条件时记录 blocked/skip，不以 fake host 通过代替。
