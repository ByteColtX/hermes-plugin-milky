# Design

## Context

动机见 proposal.md。当前命令层分别维护协议访问、白名单管理和状态观察的绑定；状态等待后检查登记版本，管理调用另有来源与运行代次。它们共享实例归属，但开放时机不同。

## Goals / Non-Goals

**Goals:** 实例绑定 module 提供登记、就绪更新和撤销的窄 interface；统一归属记录，保持各命令现有可用性。

**Non-Goals:** 合并三类能力开放时机、把关联当作授权、改 core 权限、重构连接资源、改变停止后状态展示。

## Decisions

1. 命令 module 拥有登记记录和选择规则，运行生命周期拥有实例状态并发布其变化。调用方持有不透明绑定关联，而不维护三组集合。分别抽三个登记 wrapper 仍要求调用方同步状态，因此选择以实例归属为 seam。
2. 登记时只开放可信本地观察，完成必要同步后才开放协议能力；管理可用性继续受当前运行状态约束。撤销使关联立即失效，并保留等待前后复核。停止状态是否还能被展示依照现有可信观察者的归属判断，不机械全部清空或重新绑定旧实例。
3. 来源/profile 和 core 授权各有所有者。绑定 module 只确认实例关联；管理 module 继续校验单次调用关联和代次，不能由登记信息推出授权。多实例无法唯一确认时保持降级，不猜最近会话或环境 profile。
4. 内存归属规则直接测试；Hermes 是 true external 依赖，沿用宿主 adapter 和 fake host 两种实际 adapter。主要测试跨命令或生命周期 interface，内部集合不进入断言。

## Risks / Trade-offs

- [Risk] 初始化时误开放 client。→ 用启动、同步失败、就绪三阶段测试断言网络可用性。
- [Risk] 旧读取或调用借用新运行代次。→ 等待中解绑/重连测试断言降级且无旧设置操作。
- [Risk] 一个实例撤销影响另一个。→ 多实例测试核验独立资源、关联与静态帮助。

## Migration Plan

先冻结命令回执和生命周期可用性，再引入统一归属记录并迁移绑定/撤销调用；同时更新测试和所有权文档。无持久迁移；回滚恢复原登记路径，确保只维护一套生效记录。

## Open Questions

真实宿主多 profile 分发和停止接入仍需单独证据；缺少可信范围时沿用 unsupported，不依赖未确认宿主能力。
